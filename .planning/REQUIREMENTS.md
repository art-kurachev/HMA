# Requirements — Shopping List Feature

## v1 Requirements

### Backend

- [ ] **SHOP-01**: Пользователь может сгенерировать список покупок (10 миксов) одним нажатием без параметров
- [ ] **SHOP-02**: Генерация расходует квоту пользователя (1 запрос = 1 генерация)
- [ ] **SHOP-03**: Список покупок сохраняется на сервере и привязан к Telegram ID
- [ ] **SHOP-04**: Один активный список на пользователя (перегенерация заменяет старый)
- [ ] **SHOP-05**: Пользователь может получить свой текущий список покупок
- [ ] **SHOP-06**: Пользователь может обновить список отмеченных (купленных) табаков
- [ ] **SHOP-07**: 10 миксов генерируются разнообразными (разные бренды, профили, крепости)

### Frontend

- [ ] **SHOP-08**: Кнопка "Список покупок" видна на главном экране (WelcomeScreen)
- [ ] **SHOP-09**: При отсутствии списка показывается онбординг-состояние с кнопкой генерации
- [ ] **SHOP-10**: Список показывает уникальные табаки, отсортированные по частоте использования (сначала те, что в большинстве миксов)
- [ ] **SHOP-11**: Рядом с каждым табаком — чекбокс, пользователь отмечает купленные прямо в магазине
- [ ] **SHOP-12**: Купленные табаки визуально отличаются (зачёркнуты / серые)
- [ ] **SHOP-13**: По тапу на микс раскрывается его полный состав с пропорциями
- [ ] **SHOP-14**: Кнопка перегенерации показывает диалог подтверждения ("Будет использована 1 генерация, текущие отметки сбросятся")
- [ ] **SHOP-15**: Состояние чекбоксов сохраняется на сервере (не сбрасывается при перезапуске)

## v2 Requirements (деферировано)

- Группировка табаков по бренду
- Шаринг списка (отправить другу)
- Несколько сохранённых списков
- История генераций

## Out of Scope

- Цены и магазины — нет источника данных
- Редактирование миксов вручную — слишком сложно для v1
- Рекомендации на основе списка — деферировано
