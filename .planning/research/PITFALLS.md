# Pitfalls — Shopping List Feature

## Грабли LLM

### 10 одинаковых миксов
**Проблема:** GigaChat может повторить похожие миксы или использовать одни и те же табаки во всех 10.
**Решение:** В промпте явно требовать разнообразие — разные бренды, разные профили (фруктовый, свежий, десертный и т.д.), разные крепости. Добавить в `FORBIDDEN_RULES` или прямо в промпт.
**Фаза:** Backend / промпт.

### JSON парсинг на 10 миксов
**Проблема:** Больший JSON → выше вероятность truncation или невалидного JSON.
**Решение:** Явно указать в промпте "ровно 10 миксов", добавить retry логику или валидацию на бэке. Существующий паттерн с `json.loads()` достаточен, но нужна проверка `len(mixes) == 10`.
**Фаза:** Backend / промпт.

## Грабли UX

### Список покупок vs Полка
**Проблема:** Пользователь может запутаться — чем список покупок отличается от "Полки"?
**Решение:** Чёткие названия и иконки. Полка = "сохранённые миксы которые я уже попробовал". Список покупок = "что купить в следующий раз".
**Фаза:** UI/UX.

### Перегенерация без предупреждения
**Проблема:** Пользователь случайно жмёт "Обновить" и теряет отмеченные товары + тратит квоту.
**Решение:** Диалог подтверждения "Обновить список? Текущие отметки будут сброшены. Будет использована 1 генерация."
**Фаза:** Frontend.

### Пустой экран при первом входе
**Проблема:** Пользователь открывает раздел и видит пустой экран — непонятно что делать.
**Решение:** Onboarding состояние с CTA кнопкой "Сгенерировать список покупок" и кратким объяснением фичи.
**Фаза:** Frontend.

## Грабли Backend

### Race condition при одновременных запросах
**Проблема:** Пользователь дважды быстро нажал "Сгенерировать" → два LLM запроса → два upsert.
**Решение:** UniqueConstraint на `user_id` + ON CONFLICT DO UPDATE (upsert). Или блокировка на уровне очереди (уже есть `llm_queue.py`).
**Фаза:** Backend DB.

### Большой JSONB
**Проблема:** 10 миксов × ~5 табаков × названия = ~2-3KB JSON. Не проблема, но надо контролировать.
**Решение:** Ограничить названия миксов (уже есть в промпте), не хранить лишние поля.
**Фаза:** Data model.

## Грабли квоты

### "Это же не микс, почему тратит квоту?"
**Проблема:** Пользователь думает что список покупок бесплатный (это же просто список, не курение).
**Решение:** Явно указать на UI при генерации: "Будет использована 1 генерация". Это ожидание нужно сформировать заранее.
**Фаза:** Frontend UX copy.
